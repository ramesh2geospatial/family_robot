## Summary
The Access Control Layer permission evaluator returns allowed=True if an unregistered or custom permission is checked, leading to a fail-open model.

## Spec reference
- Requirement: REQ-003
- Spec basis: docs/specifications.md:330-335
- Behavioral contract quote: "Role-based ACL enforced centrally; every privileged action is logged to a tamper-evident audit log."

## The code
At [`packages/core/governance/acl.py:101-106`](file:///d:/GeoNagrik/Dev/git/family_robots/packages/core/governance/acl.py#L101-L106), the parser checks `_PERMISSION_MATRIX.get(permission)` and returns `ACLResult(allowed=True)` if it is not present.

## Observable consequence
Misspelled permissions or custom permissions default to being allowed for all roles, including guests and children, bypassing access checks.

## The fix
```diff
--- a/packages/core/governance/acl.py
+++ b/packages/core/governance/acl.py
@@ -103,4 +103,4 @@
         if allowed_roles is None:
-            # Unknown permission → allow by default (fail-open for unknown skills)
-            logger.warning("Unknown permission '%s'; allowing by default.", permission)
-            return ACLResult(allowed=True)
+            # Unknown permission → reject (fail-closed for security)
+            logger.warning("Unknown permission '%s'; denying access.", permission)
+            return ACLResult(allowed=False, reason=f"Unknown permission '{permission}'", spoken_denial="Sorry, I don't recognize that permission.")
```
