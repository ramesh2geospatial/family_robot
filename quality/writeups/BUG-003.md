## Summary
The Raspberry Pi battery monitor loop lacks charging-state validation, causing safe-shutdown loops when recovering mains power.

## Spec reference
- Requirement: REQ-005
- Spec basis: docs/specifications.md:380-385
- Behavioral contract quote: "survive power cuts (UPS + SQLite WAL); watchdog-restart workers."

## The code
At [`packages/adapters/raspberrypi/power.py:73-85`](file:///d:/GeoNagrik/Dev/git/family_robots/packages/adapters/raspberrypi/power.py#L73-L85), the monitor loop calls the low power callback unconditionally when battery percentage falls below 15%, without querying if the UPS is charging.

## Observable consequence
On power cut recovery, the system reboots but the battery remains below 15%. Because the adapter triggers the safe-shutdown callback regardless of charging status, the Pi enters a boot-loop.

## The fix
```diff
--- a/packages/adapters/raspberrypi/power.py
+++ b/packages/adapters/raspberrypi/power.py
@@ -80,2 +80,3 @@
-                    if pct is not None and pct < 15:
+                    is_charging = await self.is_charging()
+                    if pct is not None and pct < 15 and not is_charging:
```
