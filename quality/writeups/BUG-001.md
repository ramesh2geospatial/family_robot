## Summary
The orchestrator main loop classifies voice commands but routes them directly to state modifiers without calling the access control validation.

## Spec reference
- Requirement: REQ-001
- Spec basis: docs/specifications.md:330-335
- Behavioral contract quote: "Role-based ACL enforced centrally; every privileged action is logged to a tamper-evident audit log."

## The code
At [`apps/familyrobot/main_loop.py:150-160`](file:///d:/GeoNagrik/Dev/git/family_robots/apps/familyrobot/main_loop.py#L150-L160), the main loop classifies intents and then directly calls `_handle_intent()` without checking roles or calling `ACL.check_intent()`.

## Observable consequence
When a child or guest triggers a voice command for a restricted appliance (e.g. "turn on the geyser"), the orchestrator executes the command without checking their role, violating the safety policy matrix.

## The fix
```diff
--- a/apps/familyrobot/main_loop.py
+++ b/apps/familyrobot/main_loop.py
@@ -154,2 +154,8 @@
-        raw_response = await _handle_intent(intent, text, home, llm, memory)
-        response = format_response(raw_response, intent.name)
+        acl_result = components["acl"].check_intent(user, intent.name, intent.entities)
+        if not acl_result.allowed:
+            response = acl_result.spoken_denial
+        else:
+            raw_response = await _handle_intent(intent, text, home, llm, memory)
+            response = format_response(raw_response, intent.name)
```
